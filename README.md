# 进销存软件（IVS）

独立进销存系统：**整车 / 动力电池 / 其他产品**。
业务主链路：**政策手工录入 → 订单选政策（预享受项）→ 实销 → 申请兑现 → 厂家红字发票 → 返利资金池 → 抵扣车款**。

- 独立仓库、独立数据库、独立部署，与「重卡销售 CRM」无任何运行时依赖
- 完整方案见 [进销存系统落地方案_v1.0.md](进销存系统落地方案_v1.0.md)

### ✅ M4-1 返利资金池与抵扣车款（2026-10-17 交付）

| 项 | 内容 |
|---|---|
| 数据库 | Flyway `V6`：资金池 / 按厂家子余额 / 资金流水（含 `remaining_amount`）/ 抵扣单 / 抵扣明细；采购收货单增加 `offset_amount` |
| 一个池、按厂家分账 | 全公司只有一个资金池，余额按厂家分子账；**A 厂返利只能抵 A 厂车款** |
| 只进已到账 | 入池只接受已到账返利（红字发票 / 厂家打款 / 权益结算），`allow_pre_offset` 固定 false —— **不允许预抵扣** |
| 抵扣规则 | **本次抵扣 = min(该厂家可用余额, 本单金额)**：余额小于本单则一次抵完，余额大于本单则本单抵满、**剩余余额留到下一单** |
| 无需审批 | 入库单确认时勾选入池记录即可抵扣，不设审批环节，全程留痕 |
| 双向追溯 | 抵扣明细 FIFO 指向**具体哪几笔返利入池记录**（含来源单号）；由返利可查抵了哪张采购单，由采购单可查用了哪几笔返利 |
| 回补 | 取消抵扣自动回补子余额与入池记录可用额，并写 `ADJUST_IN` 流水 |
| 模块边界 | 采购声明 `RebateOffsetPort`，实现在 app 层委托 policy 模块 → 业务模块之间零直接依赖 |

### 固定发布规则（自 v1.9.8 起）

每次完成功能开发或缺陷修复后，默认同时完成以下发布动作，不再只停留在本地构建：

1. 清理旧构建目录和过期安装包，仅保留最新版产物；

3. 更新网页登录版、Windows 安装包、Windows 绿色版和 Android APK；
4. 发布到同一 GitHub 仓库并生成新的语义化版本 Release；
5. 用最新 Windows 安装包替换桌面上的 `容大进销存系统.exe`；
6. 验证固定网页地址、最新 Release 和在线 API 健康状态。

上传覆盖前仍需确认目标仓库名称和公开/私有可见性，避免误覆盖其它仓库。

## M4 业务验收

运行 `scripts/verify-m4-uat.ps1` 会自动完成：

1. 创建 UAT 厂家 / 车型 / VIN / 客户；
2. 录入并发布两条叠加政策；
3. 创建订单并生成预享受项；
4. 实销登记、复核、生成正式权益；
5. 合并申报、厂家确认 12,500（申报 13,000，差异 500）；
6. 红字发票入池 12,500；
7. 校验单车政策成本、差异报表、9 个页面路由与 6 个报表接口。

> 脚本每次运行都会新建一组 `UAT-` 前缀样例数据，便于反复验收；正式数据请勿使用该前缀。

采购明细专项验收运行 `scripts/verify-purchase-detail-uat.ps1`，会验证：订单编号、车系、配置、数量、单价、总计车款、两项返利政策、采购审核、两条 VIN 不同单车采购价、库存金额及采购单编号搜索。
